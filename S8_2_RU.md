# SecurityLab S8.2 — отмена, события, diff кандидатов

Обновление поверх S8.1.1. Внешний вид сохранён, используются существующие экраны.

## Установка

1. Дождитесь завершения активного прогона в старой версии. Остановите сервер Ctrl+C.
2. Скопируйте содержимое update из архива в корень SecurityLab с заменой файлов.
3. В PowerShell из корня:

```powershell
py -3 -m securitylab.dashboard --state "$env:TEMP\SecurityLab_S72_DemoState"
```

4. Откройте http://127.0.0.1:8765 и нажмите Ctrl+F5.

Готовая UI-сборка включена, npm не нужен. Docker-образы пересобирать не требуется:
изменения относятся к коду управляющего процесса на хосте. Модель повторно не скачивается.
Пользовательский state и AI-профили архив не заменяет.

## Что добавлено

### Отмена активного запуска

Кнопка «Отменить» доступна активному заданию, созданному текущим сервером.
POST cancel принимает запрос и возвращает CANCEL_REQUESTED. UI показывает
«Останавливаем…». Worker передаёт сигнал в Hermes и HTTP-исполнитель,
останавливает прикреплённый процесс и выполняет штатную очистку принадлежащих
прогону контейнеров/сети. Команды очистки не прерываются сигналом отмены.

STOPPED (в UI «отменён») появляется только после завершения worker с подтверждённой
очисткой во всех созданных AI/HTTP receipts. FAIL/NOT_TESTED/нечитаемый receipt
оставляет BLOCKED. Уже полученные этапы, кандидаты и receipts сохраняются.
Ни git merge, ни изменение исходного репозитория не выполняются.

Отмена не мгновенная: короткие Docker-команды завершаются в своих ограниченных
тайм-аутах, затем выполняется очистка. Общий контейнер model не удаляется и не
перезапускается; остановка чужих запросов или мгновенная разгрузка GPU не обещаются.
Если запрос поступил уже во время финальной фиксации изолированного коммита,
запуск может успеть завершиться PASS: финальный результат важнее принятия запроса.

Старые CLI-прогоны и задания другого сервера отменять нельзя. После аварийного
завершения процесса восстановленный прогон остаётся INTERRUPTED/BLOCKED;
эта версия не обещает очистку после принудительного убийства процесса/хоста.

### События и этапы

Red → baseline → Blue → candidate → при необходимости второй кандидат → recheck
→ изолированный коммит → результат. Начало, ожидание и завершение этапов сохраняются
в dashboard_jobs/<id>.live.json. UI получает их обычным HTTP-поллингом.
Сохраняются последние 200 событий. Токены модели и подробный stderr не стримятся:
полные доступные данные вызовов остаются в receipts. Во время генерации показывается
ожидание, а не выдуманный процент. После перезапуска сервера активные стадии помечаются
прерванными, автоматического повтора нет.

### Отдельный diff кандидатов

Для каждого полученного структурированного кандидата сохраняются candidate_N.py
и candidate_N.patch. Каждый diff сравнивается с исходным снимком, а не с предыдущей
попыткой. Исправлена прежняя подстановка итогового diff во все строки попыток.
Добавлен GET /api/runs/{id}/attempts/{1|2}/diff; diff отображается в карточке попытки
и доступен как текстовый артефакт, даже если итоговый запуск BLOCKED.
Если AI-ответ не дошёл до допустимого кандидата (например, неверный JSON), diff нет:
причина остаётся в receipt. Исторические прогоны до S8.2 не получают выдуманных diff.
Экспорт подтверждённого патча по-прежнему требует PASS и отдельный Git-коммит.

## Проверка на вашем ПК

1. Запустите Docker Desktop и существующий model с GPU override:

```powershell
docker desktop start
docker compose -f compose.ai.yaml -f compose.ai.gpu.yaml up -d model
```

2. В UI выберите тестовый проект, существующий снимок, app/main.py,
   политику record_ownership_extended и профиль qwen-local.
3. Пройдите предпроверку, запустите проверку. Откройте карточку: должны появиться
   реальные стадии и события ожидания Red/Blue.
4. Нажмите «Отменить» во время ожидания модели. Дождитесь финального статуса,
   затем откройте receipts и проверьте cleanup. Не закрывайте консоль во время очистки.
5. Обновите страницу: результат и журнал должны сохраниться.
6. Для проверки diff нужен отдельный прогон, успевший получить кандидат Blue.
   PASS для проверки интерфейса не обязателен; BLOCKED должен сохранять реальную причину.

## Проверки разработчика и границы

11 новых S8.2 тестов: запрос/завершение отмены, отмена до AI, после baseline,
отмена AI/HTTP с PASS и FAIL очистки, передача stop в реальные классы адаптера/брокера
с подменённым Docker transport, отдельные diff, лимит журнала, восстановление после
перезапуска, ограничения endpoint diff. Docker/model в этих тестах имитируются;
Git в проверках workflow настоящий и изолированный.

Дополнительно прошли: 11 dashboard, 51 access, 17 HTTP, 10 FastAPI, 37 AI/config/limits
тестов, DTO-скрипт и сборка TypeScript/Vite. Новая браузерная приёмка и настоящий
Docker/Ollama на Windows в этой среде не выполнялись.

Не добавлены: очередь, CPU/GPU-метрики, редактор/загрузка моделей, универсальный
сканер, многомодульные исправления, объединённая история всех старых режимов.
Следующий шаг — приёмка S8.2 на Windows, затем расширение выбора entry/адаптеров.
