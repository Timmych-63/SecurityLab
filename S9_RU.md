# S9.0 — TicketDesk, многофайловый режим, русские подписи

## Что входит

- update/ — обновление SecurityLab поверх S8.3, готовая сборка UI и исходники.
- TicketDesk/ — только приложение и публичные требования. Именно эту папку добавлять в SecurityLab.
- operator-policy/ticketdesk_access.json — внешняя политика первой фазы.
- PRIVATE_OPERATOR.zip — ответы, дополнительная проверка и контрольное исправление. Хранить отдельно, НЕ добавлять в проекты или исходники SecurityLab, НЕ передавать модели.
- SecurityLab_S9.bundle — история исходников SecurityLab для восстановления; закрытых ответов и стенда в ней нет.

## Реализовано

В форме нового запуска появился переключатель «Анализ нескольких файлов». CLI: существующая команда repo access-ai с дополнительным --multi-file.

В этом режиме AI получает все выбранные Python-модули одного сервиса (до 8 файлов и 18000 байтов суммарно). Точка входа по-прежнему ограничена 12000 байтами. Транспорт запроса/ответа ограничен 30000 байтами: JSON-экранирование и дублирование точки входа могут привести к отказу раньше общего лимита исходников. Не помещающийся пакет отклоняется, а не обрезается. Это полный контекст небольшого пакета, не индексатор огромных репозиториев.

Red может указать любой из переданных файлов. Blue возвращает объект files: путь -> полный исходник для изменяемых файлов. Добавление новых путей, выход из пакета, переименование и удаление файлов не поддерживаются. Остальные файлы сохраняются. Изменения применяются к отдельной копии Git, общий diff сохраняется по всем файлам. Повторная попытка получает весь предыдущий пакет. Проверки исходника, кандидата и повторного прогона выполняются по неизменяемой внешней политике. Проверяются хеши артефактов, receipts, образов и исходного снимка. Старый однофайловый режим сохранён.

В UI русифицированы основные статусы, заголовки результатов, этапы, таблица проверок, режимы запуска, подписи модели и каталога данных. Технические коды сохранены в подробностях. Исходные ошибки библиотек, тексты AI и JSON-артефакты не переводятся автоматически, чтобы не исказить доказательства. Это не полная локализация всех внешних сообщений.

## Установка на Windows

1. Завершите/отмените текущие задания, остановите dashboard (Ctrl+C).
2. Скопируйте содержимое update/ в существующий корень SecurityLab с заменой.
3. Скопируйте operator-policy/ticketdesk_access.json в examples/security_policies/ установленного SecurityLab. Другие материалы оператора туда не копировать.
4. TicketDesk оставьте отдельно от корня SecurityLab и закрытых материалов, например C:\SecurityLabTargets\TicketDesk.
5. Пересоберите Hermes: изменился протокол предложений.

```powershell
docker compose -f compose.ai.yaml --profile build build hermes
```

Если образ проверки FastAPI ещё не собран:

```powershell
docker build -f docker/FastAPI.Dockerfile -t securitylab-fastapi:local .
```

Поднимите модель с теми же Compose-файлами, с которыми она работала раньше (в том числе вашим GPU override). Не заменяйте пользовательскую AI-конфигурацию. Пример при наличии compose.ai.gpu.yaml:

```powershell
docker compose -f compose.ai.yaml -f compose.ai.gpu.yaml up -d model
py -3 -m securitylab.dashboard --state "$env:TEMP\SecurityLab_S72_DemoState"
```

Откройте http://127.0.0.1:8765 и Ctrl+F5.

## Первый прогон

1. Добавьте локальный путь к папке TicketDesk. Если проект требует Git-репозиторий, выполните в этой папке `git init`, `git add .`, `git -c user.name=Lab -c user.email=lab@localhost commit -m "Initial application"`.
2. Создайте снимок через интерфейс.
3. Новый запуск: выберите проект и снимок, сервис `.`, точку входа `app/main.py`.
4. Включите «Анализ нескольких файлов».
5. Политика: `ticketdesk_access`; модель: ваша действующая конфигурация.
6. Выполните предпроверку и запустите.
7. Сохраните результат, причину отказа (если есть) и diff. PASS на этой политике не означает прохождение всех закрытых случаев.

В первой фазе SecurityLab видит конкретные проверки внешней политики. Он не получает скрытые ответы и контрольное исправление. Самостоятельное построение гипотез без списка случаев — следующий этап, здесь оно не реализовано.

## Границы стенда

TicketDesk — система заявок с пользователями, руководителем, администратором, комментариями, созданием заявок и изменением статуса. Данные только в памяти. Идентификация через X-Test-User моделирует доверенный шлюз в изолированном тесте; это НЕ настоящая система входа и не production-авторизация.

Текущий автоматический профиль SecurityLab проверяет GET-доступ по заданным случаям. POST/PATCH и дополнительные регрессии проверяются закрытым HTTP-набором отдельно. Автоматического запуска произвольных тестов проекта, БД, установки его зависимостей и поддержки любых языков в этом обновлении нет.

- 51 существующий тест access, 6 новых тестов пакета и интеграции dashboard.
- 13 тестов S8.2/S8.3, 11 тестов dashboard; 37 тестов AI; всего 118 Python-тестов прошли.
- React/DOM: многофайловый переключатель сбрасывает предпроверку, выбранный профиль передаётся в запуск; сохранение вкладок/фокуса; DTO и форматирование; production build.
- Закрытый набор TicketDesk: 36 случаев на авторском исходнике и контрольном исправлении. Проверен локально через FastAPI TestClient; результаты сохранены в закрытом архиве. Версия локального FastAPI 0.141.1, Docker-образ проекта использует 0.115.12; реальный Docker-прогон на вашей машине ещё необходим.
- Пакетные pipeline-тесты используют подставные модель/HTTP-наблюдатель и настоящий изолированный Git. Они НЕ доказывают качество исправлений реальной модели.

Ни Docker/Hermes-прогон нового стенда, ни визуальная приёмка браузера Windows в среде подготовки не выполнены. Итог S9 — готовый стенд, ограниченный многофайловый режим и русские подписи; пользовательский прогон нужен для подтверждения интеграции.
