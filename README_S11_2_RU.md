# S11.2 — гипотезы с автопроверкой путей (исправление живого прогона №5)

Хотфикс для SecurityLab S11.1. Остановите dashboard, сделайте резервную копию папки,
примените `apply_S11_2.ps1` (или скопируйте содержимое `update/` в корень SecurityLab
с заменой файлов и пересоберите образ). Каталог `.securitylab` (история запусков и
настройки) не изменяется.

## Что случилось в прогоне №5

Решение 1 отработало штатно: модель выбрала `http`, исполнитель сделал 1 запрос,
наблюдение сохранено. На решении 2 модель дважды предложила гипотезы о паре
путь+аккаунт, которую **не зондировала**, и прогон погиб на валидаторе:

```
red attempt 2: proposal rejected: Hypothesis must reference an HTTP observation
you made in this research run; run an http action first
```

Хронометраж: подготовка 0.05 c → решение 1 через 144 c (транспорт здоров) →
решение 2 → 739 c двух попыток с корректирующей заметкой → BLOCKED при
10 неиспользованных решениях. Корректирующая заметка «run an http action first»
малую модель не спасла: она не умеет сама извлекать свои пары из сырого HISTORY.

## Что изменилось (5 правок)

1. **Запрос модели теперь показывает наблюдения явно.** В prompt добавлен блок
   `OBSERVED HTTP CHECKS` — список пар путь+аккаунт+статус, которые модель реально
   зондировала, и правило: гипотеза валидна только по этим парам; новую пару —
   сначала `http`, потом гипотеза.
2. **Автопроверка путей из отклонённых гипотез (главное).** Если модель предложила
   гипотезы о незондированных парах, ядро само зондирует ровно эти пары через
   обычную независимую стадию наблюдения (стадия `http_assist_NN`, с учётом
   бюджета запросов и времени, один раз на решение, до 8 проверок) и возвращает
   модели повторный запрос: наблюдения уже в истории, переотправь те же гипотезы.
   Тупик превращается в прогресс.
3. **Корректирующая заметка стала точечной.** При отклонении она перечисляет
   незондированные пары из отклонённого ответа и оба допустимых исправления
   (ограничить гипотезы наблюдаемыми парами или сначала вернуть `http` с этими
   парами) плюс список наблюдаемых пар.
4. **Red устойчива к двойным отклонениям.** Решение, отклонённое дважды,
   больше не убивает прогон: решение списывается, причина попадает в историю
   модели и `decision_NN.json`, цикл продолжается. Два таких решения подряд —
   остановка `BLOCKED` с сохранёнными результатами (испорченная модель не
   сжигает весь бюджет). Транспортные сбои (TIMEOUT, обрыв) по-прежнему
   останавливают прогон сразу.
5. **Сжатие истории больше не выбрасывает наблюдения.** При превышении
   транспортного бюджета первыми удаляются строки чтения/поиска; строки с
   HTTP-наблюдениями защищены — иначе старые наблюдения пропадали бы из вида
   модели и легально ссылающиеся на них гипотезы становились бы невалидными.

Дополнительно: worker при отклонении печатает `AI_PROPOSAL_JSON` (отклонённое
предложение попадает в receipt и в исключение `ProposalRejected` вместе с id
вызова) — в `summary.json` прогона видно, что именно модель предложила.

## Проверка поставки

Маркеры в файлах после распаковки: `OBSERVED HTTP CHECKS`, `http_assist`,
`AI_PROPOSAL_JSON`, `assist_retry_note`, `corrective_feedback`,
`sampling_overrides`, `frequency_penalty`, `AI_RESPONSE_JSON`.

```powershell
py -3 -m unittest discover -s tests -p "test_research_*.py" -v
py -3 -m unittest tests.test_ai -v
docker compose -f compose.ai.yaml --profile build build hermes
py -3 -m securitylab ai-smoke
```

ВАЖНО: код worker'а внутри Docker-образа. Шаг `COPY securitylab` в сборке не
должен быть `CACHED` — иначе продолжит работать прежний код. `apply_S11_2.ps1`
проверяет это сам и останавливается с ошибкой.

## Что ждать в прогоне №6

- Строка `Автопроверка путей из отклонённых гипотез: N запрос(ов)` и стадия
  `http_assist_NN` в дашборде, если модель снова предложит незондированные пары.
- `ai_calls` с `"rejected": true` и `"reason"` для отклонённых попыток — без
  гибели прогона.
- Если модель упорно выдаёт мусор два решения подряд — `BLOCKED` с причиной
  `Формат ответа модели отклонён в двух решениях подряд`; пришлите
  `summary.json` и указанный в ошибке receipt — дальше правим prompt/сэмплинг.
