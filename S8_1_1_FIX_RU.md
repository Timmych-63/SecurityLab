# SecurityLab S8.1.1

Исправление поверх установленного S8.1.

1. Остановите сервер дашборда через Ctrl+C (при отсутствии активного запуска).
2. Содержимое update скопируйте в корень SecurityLab с заменой файлов.
3. Запустите из корня:

```powershell
py -3 -m securitylab.dashboard --state "$env:TEMP\SecurityLab_S72_DemoState"
```

4. Откройте http://127.0.0.1:8765 и обновите страницу через Ctrl+F5.

Тестовый Python-проект без файла зависимостей теперь доступен в форме нового запуска.
Дашборд учитывает Python-файлы инвентаризации и точки входа из сохранённых снимков,
а не только список сервисов по manifest-файлам. Это не подтверждение совместимости:
прежняя проверка снимка, выбранного entry, ограниченного пакета и внешней политики
всё равно обязательна перед запуском. Проект Node без Python не становится поддерживаемым.

Карта API показывает фактические маршруты и отдельную колонку готовности:
Работает / Частично / Не реализовано / Заглушка, с конкретными ограничениями.
Отдельный GET snapshots убран из обещаний; снимки возвращаются внутри GET projects.
Указан реальный ключ runId, уточнено, что проверка модели не запускает генерацию.

State, исходные проекты, снимки, модели и AI-профили не изменяются.
Пересборка Docker и скачивание модели не нужны. Готовая UI-сборка включена.

Проверки: 11 тестов dashboard прошли, включая отсутствие manifests и отказ для
неподдерживаемого проекта; TypeScript/Vite сборка прошла.
Браузерная приёмка и запуск модели на Windows остаются проверкой на вашем ПК.
