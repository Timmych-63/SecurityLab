# SecurityLab S8.2.1 — обновление запусков без сброса страницы

Обновление поверх S8.2 Control Events Diffs. Изменены только интерфейс и его тесты; ядро, ограничения проверки и AI-конфигурация сохранены.

## Причина и исправление

Обработчик reportConnection создавался заново при каждом обновлении глобального состояния, включая секундный таймер. Эффект загрузки карточки воспринимал это как изменение зависимости и сбрасывал данные в skeleton. Исчезновение высокого содержимого приводило к сбросу прокрутки.

- Обработчик связи теперь стабилен.
- Первичная загрузка показывается при смене прогона/backend; обычные обновления сохраняют содержимое карточки.
- Опрос карточки последовательный, примерно каждые 2,5 секунды после ответа. Завершённый прогон больше не опрашивается карточкой; глобальная проверка активности остаётся.
- После отмены данные обновляются без удаления содержимого.
- При сетевой ошибке остаются последние данные с предупреждением; повторные попытки с увеличением задержки до 15 секунд.
- Ответы устаревшего запроса после смены прогона игнорируются.
- Компонент фильтра списка вынесен за пределы функции экрана: выбранные значения, DOM-элемент и фокус сохраняются при обновлении.

## Установка

1. Дождитесь завершения или отмените активный прогон. Остановите dashboard в его PowerShell через Ctrl+C.
2. Скопируйте **содержимое** папки `update` из архива в корень SecurityLab с заменой файлов. Папка `dashboard` должна попасть рядом с `securitylab`, а не внутрь дополнительной папки update.
3. Запустите:

```powershell
py -3 -m securitylab.dashboard --state "$env:TEMP\SecurityLab_S72_DemoState"
```

4. Откройте http://127.0.0.1:8765 и один раз нажмите Ctrl+F5.

Docker-образы пересобирать и npm устанавливать для использования не нужно: готовый dist включён. Старые файлы dist с другими хешами могут остаться; новый index.html использует новые файлы.

## Проверка на вашем ПК

- Откройте активный прогон, выберите «Проверки» или «Предложения и попытки», прокрутите вниз. Подождите 10–15 секунд: страница не должна возвращаться наверх или мигать загрузкой.
- В списке запусков выберите фильтр, оставьте фокус на нём и дождитесь обновления. Выбор должен сохраняться.
- Нажмите отмену: сначала ожидание остановки, затем статус ядра. Автообновление не должно возвращать на первую вкладку.

Изменение самого набора данных (например, исчезновение строки из фильтра «выполняется») закономерно может менять высоту списка. Исправление устраняет периодическое удаление всей карточки, а не замораживает содержимое.

## Выполненные проверки

- React + jsdom: секундные тики не вызывают загрузку карточки; фоновый запрос сохраняет выбранную вкладку и её DOM; успешный ответ, ошибка и обновление после действия не удаляют содержимое; устаревший ответ игнорируется; завершённый прогон прекращает опрос карточки; фильтр и фокус сохраняются при тиках и обновлении списка.
- DTO integration cases PASS.
- TypeScript/Vite production build PASS.

Тест запускается из dashboard: `npm ci`, затем `npm run test:refresh`. Он использует подставной HTTP-адаптер и реальные React-компоненты, не запускает Docker/модель. jsdom не рассчитывает геометрию страницы: фактическая прокрутка и визуальная проверка в браузере Windows остаются для проверки на ПК. Браузерный запуск в среде подготовки недоступен.

На присланном скриншоте STOPPED и NOT_EVALUATED подтверждают отображение отмены. Сам скриншот не подтверждает cleanup receipts контейнеров.
