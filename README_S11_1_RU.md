# S11.1 — единый вход + самостоятельный цикл исследования

Обновление для SecurityLab S11.0 (старые режимы S7.2/S9/S10 и демо сохранены).
Остановите dashboard, сделайте резервную копию папки, скопируйте содержимое `update/`
в корень SecurityLab с заменой файлов. Каталог `.securitylab` (история запусков и
настройки) не изменяется.

## Быстрая проверка

```powershell
py -3 -m unittest discover -s tests -p "test_research_*.py" -v
py -3 -m unittest tests.test_dashboard_research -v
py -3 -m securitylab repo research --help
py -3 -m dashboard   # если запуск велик; стандартно: python -m securitylab.dashboard --state <state>
```

Сборка dashboard уже включена (`dashboard/dist`). Для разработки UI: `cd dashboard; npm ci; npm run build`.

## Что нового

- Новый запуск → чекбокс «Самостоятельное исследование»: подготовка (документация ≤12 КБ,
  аккаунты, бюджет) → предпроверка из шести шагов с конкретными причинами неготовности → запуск.
- Цикл: Red сама изучает исходники и выбирает GET-гипотезы (без списков дефектов);
  нарушение считается подтверждённым только после независимого воспроизведения на свежем стенде;
  Blue предлагает минимальный патч, который проверяется baseline → candidate → recheck → изолированный commit.
- Бюджет (время/решения/запросы) применяется исполнителем программно и показывается в UI без процентов.
- Горячие исправления по живым прогонам: усечённый/деградировавший/пустой ответ модели и отклонение
  по контракту — это отклонённая попытка (один корректирующий запрос с компактной обратной связью;
  дважды → BLOCKED, накопленные результаты сохранены). Держите `max_output_tokens` умеренным
  (рекомендуется 2048): на медленной генерации длинный лимит не даёт ответу успеть до дедлайна
  `timeout_seconds` (максимум 1200 с) — прогон останавливается TIMEOUT без повтора. Против
  зацикливания — `frequency_penalty = 0.4`, `presence_penalty = 0.2` (необязательные ключи 0..2).
- ВАЖНО: код AI-worker'а находится внутри Docker-образа. После копирования файлов update-архива
  пересоберите образ: `docker compose -f compose.ai.yaml --profile build build hermes`, затем
  `py -3 -m securitylab ai-smoke`. Без пересборки продолжит работать прежний код worker'а.
- `Another worker owns this state directory` = прежний dashboard/CLI-процесс ещё запущен с этим
  state-каталогом: закройте его и запустите заново (файл замка удалять не нужно).

Подробности и ограничения: `docs/S11_1_RESEARCH_CYCLE_RU.md`, план: `docs/RESEARCH_PLAN_RU.md`.
Живая модель и Docker на этой сборке выполняли подготовку, решения Red и HTTP-наблюдения; полный
цикл (гипотезы → подтверждение → Blue-патч) — приёмка (этап 5) впереди.
