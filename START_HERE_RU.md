# SecurityLab S8.1 — интеграция дашборда и выбор AI-профиля

## Установка и запуск

Обновление предназначено для SecurityLab S7.4. Сохраните копию папки программы,
затем распакуйте содержимое `update/` из архива в корень SecurityLab с заменой файлов.
State, пользовательский ai.local.toml и старые отчёты архив не содержит и не заменяет.
Готовый `dashboard/dist` включён: для обычного запуска Node/npm не нужны.

В PowerShell из корня проекта:

```powershell
py -3 -m securitylab.dashboard --state "$env:TEMP\SecurityLab_S72_DemoState"
```

Откройте http://127.0.0.1:8765 . Должна появиться надпись о подключении SecurityLab.
Python одновременно раздаёт UI и API; запуск через `npx serve dist` оставляет интерфейс
в демонстрационном режиме и не подключает ядро. Дизайн сохранён.
Альтернативный запуск: `powershell -ExecutionPolicy Bypass -File .\scripts\Start-Dashboard.ps1`.
Оставляйте консоль работающей. Закрытие вкладки не останавливает проверку.
Ctrl+C прекращает HTTP-сервер, но процесс ждёт завершения активного задания и очистки.

Для AI-проверок Docker Desktop и model должны работать. Ваш GPU override сохраняется:

```powershell
docker compose -f compose.ai.yaml -f compose.ai.gpu.yaml up -d model
```

Пересобирать Hermes для этого обновления не требуется, если образ S7.4 уже собран.
Предпроверка требует существующие securitylab-demo:local, securitylab-fastapi:local,
securitylab-hermes:s4 и приватную internal bridge сеть профиля.

## Выбор модели

В «Настройки и диагностика» и «Новый запуск» подключён реальный выбор AI-профиля.
Профили — TOML оператора в `ai-profiles/`. В поставке:

- `default`: SECURITYLAB_AI_CONFIG при старте сервера либо встроенные настройки S7.4;
- `qwen-local`: явная конфигурация текущей qwen3.5:2b.

Для другой модели скопируйте `ai-profiles/qwen-local.toml` под новым именем и измените
`model` вместе с `model_digest`. Полный digest — 64 hex без префикса sha256:.
Используйте digest реально установленной модели. Обновите страницу и выберите профиль.
Никаких выдуманных digest для будущих моделей в поставке нет.

Проверка записи вызывает валидатор ядра. Проверка модели обращается к `/api/tags`
из ограниченного контейнера в приватной сети и сверяет точное имя и digest.
Она не скачивает модель, не проверяет качество генерации и фактический объём контекста.
Сам Hermes повторно проверяет ограничения при запуске.
Требование текущего Hermes: контекст 64000..131072, ответ 256..4096 токенов,
тайм-аут вызова 120..1200 секунд. Выбор модели не снимает ограничения железа.

Выбор сохраняется в браузере. Перед запуском сервер перечитывает профиль, проверяет
предпроверку (не старше 120 секунд), фиксирует параметры и SHA256. Замена TOML или выбор
другой модели не меняют уже идущее задание. При изменении конфигурации после предпроверки
нужно повторить её. Если сохранённый в браузере профиль удалён — выберите существующий;
скрытой замены моделью по умолчанию нет.

## Что подключено

- Существующий реестр проектов и снимков из переданного `--state`, регистрация и снимки.
- Внешние политики из `examples/security_policies`; другой каталог: `--policies ПУТЬ`.
- Реальная предпроверка, один фоновый запуск access-ai, выбранный AIConfig в HermesAdapter.
- История `<state>/access_ai`, включая предыдущие CLI-запуски; HTTP-поллинг активного задания.
- Независимые baseline/candidate/recheck, исходный summary и receipts как текстовые артефакты.
- Экспорт патча только из успешного summary с изолированным Git-коммитом.
- Исправлен DTO: PASS/DONE → completed; BLOCKED/NEEDS_REVIEW → blocked; STOPPED → cancelled.
  security_verdict и finding_status больше не перепутаны. FIXED не означает универсальную безопасность.
- Модель и digest конкретного прогона в технических деталях, полная конфигурация в dashboard-job.json.
- Фиксация сбоя процесса: незавершённые задания при следующем старте становятся INTERRUPTED,
  без автоматического перезапуска. Сохранённые receipts остаются доступны.
- Только loopback, проверка Host/Origin, CSRF для POST, ограниченные чтения артефактов.

Проект не импортируется/не запускается на хосте. Используется прежний ограниченный
runner и прежняя внешняя политика; нет auto-merge или запуска произвольного shell.

## Границы S8.1

Поддерживается прежний S7.2 single-module FastAPI, а не произвольное приложение/стек.
В форме автоматически перечисляются main.py, app.py, service.py из снимков, сервис —
корень репозитория. Для иных разрешённых entry и сервисов пока используйте CLI.
Наличие entry в списке не доказывает совместимость: ядро проверяет её до запуска.
История старых scripted demo / candidate-check не подключена к дашборду.

Безопасная отмена access-ai, очередь нескольких заданий, редактор TOML, скачивание моделей,
метрики CPU/GPU и автоматическое применение патча не реализованы. Отмена отключена и
API возвращает отказ. Другие модели подключаются файлами профилей.

Исторические summaries не содержат времени старта: дата файла помечена отдельно,
длительность не вычисляется. Таблица наблюдений отражает HTTP-результаты;
body-hash и полные выводы политики смотрите в stage summary. Во время генерации
новых receipts может долго не быть — это не подтверждение зависания или успеха.

## Проверка на вашем ПК

1. Убедитесь, что UI показывает реальный проект и снимок `2ceb1b1ab21245d8ac979316cf434ed6`.
2. Откройте старый BLOCKED-прогон, summary и receipts: BLOCKED не должен стать FIXED.
3. В настройках выберите qwen-local; проверьте запись и точное наличие модели.
4. В новом запуске выберите снимок, app/main.py, нужную политику и AI-профиль.
5. Выполните предпроверку и запустите. Запишите run ID; проверьте, что он сохраняется
   после обновления страницы и виден в `<state>/dashboard_jobs`.
6. Не обязательно ждать PASS от слабой модели. BLOCKED/TIMEOUT должны оставаться видимыми
   с реальной причиной и артефактами; для исправления нужны независимые проверки.
