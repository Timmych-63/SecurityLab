# S11.0 — подготовка входа в самостоятельное исследование

Это первое обновление этапа 1, не готовый автономный сканер. Docker и модель для новой команды не нужны. Старые режимы остаются без изменений; новые документы пока не подключены к кнопке запуска в UI.

## Установка
Остановите dashboard (Ctrl+C), сделайте резервную копию папки проекта. Скопируйте содержимое update из архива в корень существующего SecurityLab S10 с заменой файлов. Настройки AI, compose.ai.gpu.yaml и сохранённое состояние в обновлении не меняются.

## Проверка
В PowerShell из корня проекта:

```powershell
py -3 -m unittest discover -s tests -p "test_research_prepare.py" -v
py -3 -m securitylab repo prepare-research --help
```

Подготовка существующего снимка (вместо SNAPSHOT_ID укажите идентификатор снимка TicketDesk из UI; не идентификатор проекта или запуска):

```powershell
py -3 -m securitylab --state "$env:TEMP\SecurityLab_S72_DemoState" repo prepare-research SNAPSHOT_ID --entry app/main.py --knowledge ".\examples\research\ticketdesk.md" --setup ".\examples\research\ticketdesk.setup.json"
```

Ожидается status=PREPARED, execution_ready=false, security_verdict=NOT_EVALUATED. Поле record указывает summary.json. Рядом лежат knowledge.md, setup.json, application_map.json. Это подготовка и статическая совместимость, не подтверждение запуска приложения, полноты документации или безопасности.
Для другого проекта нужны его документация и тестовые аккаунты. Подготовка не проверяет смысловое соответствие описания исходникам — это часть последующей работы с приложением.

Бюджет записан для будущего исполнителя, но цикл его расходования ещё не подключён. Возможности в summary обозначают планируемый ограниченный набор инструментов, не уже выполненные действия. Markdown не даёт права на дополнительные действия.
