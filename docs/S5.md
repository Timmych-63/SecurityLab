S5 adds opt-in actual-candidate verification and replay of a saved Blue proposal.
No generalized application scanning is implemented. Original S4 behavior remains
available for reproducibility. Candidate mode is bound into the AI request hash,
validated in the worker and host, and preserved across a corrective attempt.

Trust boundary: candidate AST admits only bounded computations over built-in
fixture data. Module assignment and signature are fixed; no imports, arbitrary
calls, mutations, I/O, globals, decorators, comprehensions or loops. Exact AST
equivalence to a fixed solution is no longer required. Wrong-but-admissible code
must fail independent behavioral checks. The language restriction is essential
because this phase uses same-process Python probes. It is not a general sandbox.

Verifier sends exact UTF-8 candidate bytes to S2 DockerBroker, with an immutable
test task. Host expectations cover 5 users x 3 record IDs. Baseline must match
known vulnerable behavior, candidate and a fresh-container repeat must match
fixed behavior. Host audits daemon state, exit, cleanup, flags, immutable image,
payload/source/test/run/kind bindings and persisted receipt identity. Earlier
receipts and saved source are re-read before the final verdict. There is no
cryptographic protection against a trusted host operator changing all state.

Artifacts: candidate.txt, per-container JSON receipts, summary.json; no S3 queue,
HTML export or resume for candidate verification yet. Failed execution is BLOCKED;
completed incorrect behavior is NEEDS_REVIEW. Neither assigns FIXED. Fixed-case
success is not a proof for all inputs, and model-generated expectations are not used.

Local validation includes actual execution of developer-owned sample candidates
with simulated Docker metadata; never execute user/model code locally in tests.
Regression tests cover noncanonical valid code, unchanged vulnerable code, broken
404, crashes, forbidden effects, fake success output, transport errors, receipt
tampering, CLI replay, request binding and full AI candidate orchestration.
