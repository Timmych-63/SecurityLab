# SecurityLab S6.3b — Python stdlib HTTP probe with independent client

Date: 2026-11-09. Status: **implemented and locally tested; live Docker/Windows acceptance is still pending**.

## Scope

S6.3a was accepted by the user on Windows: `test_probe.py` 12/12 PASS and actual
Docker probe `EXECUTED_UNTRUSTED`, cleanup `PASS`, verdict `NOT_EVALUATED`.

S6.3b adds an **opt-in, bounded two-container HTTP contract probe**, not an
automatic security scan. A user selects a single UTF-8 Python source file
from a verified snapshot, a set of expected GET status codes, and `--execute`.
The selected file must itself start a Python-standard-library HTTP server
listening on `0.0.0.0:8000`. Other local imports, pip dependencies, FastAPI,
Node.js, external databases and multi-service startups are **not supported**
by this mode. The two sample projects have deliberately different file names
and endpoint sets to show that expectations are not hardcoded in the platform.

The host verifies the snapshot and reads the exact file (max 96 KiB) without
running it. `job_bytes()` sends source only over stdin to the existing
`securitylab.container_worker` inside a target container. No Dockerfile or
Ollama/Hermes rebuild is required for S6.3b (uses the S6.3a demo image).

## Trust boundary and runtime

- Trusted host controls Docker through a locally pinned daemon endpoint;
  image `securitylab-demo:local` is resolved to its immutable digest.
- A new uniquely named Docker **internal bridge network** is created. Its
  `Internal=true`, driver and empty membership are verified before use.
- Target container is nonroot UID 10001, no capabilities, no-new-privileges,
  readonly root, temporary `tmpfs`, limited CPU/RAM/PID, no host mounts, no
  host port publishing, and no Docker socket. It receives ONLY source stdin.
- An independent verifier runs a constant, host-provided Python script in
  **another** container with the same restrictions and ephemeral network.
  It accesses `target:8000` and compares responses against a separately
  supplied explicit contract. No redirects, shell, or untrusted test scripts.
- Source stdout/stderr is not a source of `PASS`, `FIXED` or `SAFE`. Verified
  HTTP observations are bound to nonce, run ID, source/manifest SHA-256,
  explicit expected-path hash and pinned image. The host cross-checks
  verifier stdout with Docker daemon exit status and the saved receipt.
- Both containers and the network are forcibly removed and cleanup checked,
  including on most expected failures. Incomplete observations, inconsistent
  output/exit status, timeout, failed Docker configuration inspection, and
  cleanup failure result in `BLOCKED`.
- Successful contract: `HTTP_CHECKS_PASSED`, failing contract:
  `HTTP_CHECKS_FAILED`, transport/safety failure: `BLOCKED`. **Every result**
  has `security_verdict=NOT_EVALUATED` and `finding_status=null`; neither
  status is a vulnerability finding or a Red/Blue verification.

This two-container boundary improves integrity compared with source-supplied
tests but is not a proof against container escapes, malicious Docker hosts,
HTTP-semantic tricks, or applications tailored to public test inputs. The
trusted host/filesystem/Docker daemon remain inside the trust boundary.
Temporary container/network orphan recovery after a *hard host-process kill*
is not implemented (planned S9); orphan names carry `securitylab.ephemeral`
labels for manual inspection.

## Local implementation/tests

- `securitylab/http_probe.py`: explicit contract validation and snapshot binding.
- `securitylab/http_runner.py`: temporary network and two-container broker;
  fixed verifier and stdin-only source transport.
- `securitylab/cli.py`: `repo http-probe` CLI subcommand.
- `securitylab/profile_plan.py`: marks restricted Python HTTP probe; generic
  build/start/test/scan remain disabled.
- `examples/s6_repos/python_http_alpha` and `python_http_beta`: different
  Python-stdlib API structures, no third-party dependencies.
- `tests/test_http_probe.py`: unit/negative/transport tests. Includes real
  localhost HTTP client/server check with **trusted test-only code**; Docker
  transport is mocked, not a live Docker test.

Local tests: 17 S6.3b; 12 S6.3a; 18 S6.2; 22 S6.1; 27 DockerBroker =
**96 selected tests PASS**. Full historic suite and live new two-container
workflow were NOT verified here. No Docker daemon is available in the build
environment; never present the mocked result as real container acceptance.

## Windows commands after overlay

Copy `securitylab/cli.py`, `securitylab/profile_plan.py`,
`securitylab/http_probe.py`, `securitylab/http_runner.py`,
`tests/test_http_probe.py`, and both sample directories to the corresponding
paths in the *existing* SecurityLab project. Do not remove `.securitylab`,
models, running app data, or install a second copy of Docker.

```powershell
py -3 -m unittest discover -s tests -p test_http_probe.py -v

$state = Join-Path $env:TEMP 'SecurityLab_S63b_DemoState'
$project = py -3 -m securitylab --state "$state" repo add '.\examples\s6_repos\python_http_alpha' --name 'HTTP alpha' | ConvertFrom-Json
if ($LASTEXITCODE -ne 0) { throw 'repo add failed' }
$snapshot = py -3 -m securitylab --state "$state" repo snapshot $project.id | ConvertFrom-Json
if ($LASTEXITCODE -ne 0) { throw 'repo snapshot failed' }
py -3 -m securitylab --state "$state" repo verify-snapshot $snapshot.snapshot_id
if ($LASTEXITCODE -ne 0) { throw 'verification failed' }
py -3 -m securitylab --state "$state" repo http-probe $snapshot.snapshot_id --entry main.py --expect '/health=200' --expect '/__missing__=404' --execute
```

Expected if local image and Docker network are functional:
`HTTP_CHECKS_PASSED`, `cleanup=PASS`, two observations (`200`, `404`),
`security_verdict=NOT_EVALUATED`. No localhost port 8000 should be published.
The verifier may take a few seconds while the server starts; there is a
bounded startup retry and total verifier timeout. `HTTP_CHECKS_FAILED` means
the tested contract did not match; `BLOCKED` means no reliable test acceptance.

Optional second independent project:

```powershell
$p2 = py -3 -m securitylab --state "$state" repo add '.\examples\s6_repos\python_http_beta' --name 'HTTP beta' | ConvertFrom-Json
if ($LASTEXITCODE -ne 0) { throw 'repo add beta failed' }
$s2 = py -3 -m securitylab --state "$state" repo snapshot $p2.id | ConvertFrom-Json
if ($LASTEXITCODE -ne 0) { throw 'repo snapshot beta failed' }
py -3 -m securitylab --state "$state" repo http-probe $s2.snapshot_id --entry app.py --expect '/ready=204' --expect '/nonexistent=404' --execute
```

For blocked Docker failures, read the reported `error` and
`$state/http_probes/<run_id>/docker_receipt.json` rather than loosening
isolation or giving the application internet access. Existing
`securitylab-ai-model` and Ollama need no changes. `scan` is still BLOCKED.
