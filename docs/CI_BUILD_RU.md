# Автосборка дашборда на GitHub (план настройки)

## Зачем

Собранная сборка интерфейса (`dashboard/dist/`) должна храниться в репозитории —
это каноническая сборка, которую использует `scripts/Start-Dashboard.ps1`, когда
нет локальной `dashboard/dist.local/`.

Минифицированные файлы сборки большие (сотни килобайт), поэтому заливать их
вручную неудобно. Правильный механизм — GitHub Actions: после каждого изменения
исходников дашборда (`dashboard/src/`, конфигов сборки) Actions сам запускает
`npm ci && npm run build` и коммитит свежую сборку в `dashboard/dist/`.

## Как это работает

- Workflow: `.github/workflows/build-dashboard.yml`
- Триггеры: push в `main`, затрагивающий исходники дашборда (изменения только
  в `dashboard/dist/**`, `docs/**` и `*.md` триггер не запускают), плюс
  ручной запуск кнопкой **Run workflow** на вкладке Actions.
- Шаги: установка Node 22 → `npm ci` → `npm run build` (tsc + vite) →
  если сборка изменилась, коммит в `main` от имени `github-actions[bot]`.
- Права: workflow использует встроенный `GITHUB_TOKEN` с `contents: write`.

## Локальная сборка сильнее

При запуске дашборда `Start-Dashboard.ps1` сначала смотрит в
`dashboard/dist.local/` (если есть `index.html`), и только потом — в
`dashboard/dist/` из гита. То есть локально можно держать любую сборку
(например, применённую из zip-обновления), а гит остаётся каноническим.
`dist.local/` исключён из репозитория через `dashboard/.gitignore`.
