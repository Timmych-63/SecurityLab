# SecurityLab S6.3c — limited FastAPI image profile

Date: 2026-11-09. Base: S6.3b `deafff0`. **This is NOT generic dependency installation and NOT a vulnerability scanner.**

## Confirmed baseline

The user verified on Windows: S6.3b 17/17 unit tests PASS and real two-container
HTTP probe `HTTP_CHECKS_PASSED`, with actual 200 and 404 responses, `cleanup=PASS`,
`security_verdict=NOT_EVALUATED`. This confirms S6.3b, not the newer S6.3c.

## What changed

`repo fastapi-probe` adds a restricted profile for a **single** UTF-8 Python
source file from an already verified snapshot. The file must expose a FastAPI
ASGI object called `app`; no multi-file local imports are supported here. The
host injects a fixed, developer-authored Uvicorn launcher (`project:app`,
0.0.0.0:8000); the user repository does not control the start command.

The target runs in a separately built, labelled local Docker image
`securitylab-fastapi:local` (FastAPI 0.115.12, Uvicorn 0.34.2 direct pins).
The independent HTTP verifier remains in `securitylab-demo:local`. Both tags
are resolved by the trusted host to image SHA-256 IDs before container creation;
`docker inspect` verifies the actual target and verifier image IDs and
restrictions. App source arrives via stdin to the pre-existing worker. Docker
creation/configuration and cleanup are performed by the trusted broker.

There is **no `pip install` from a repository requirements file or manifest**,
no repository shell scripts, no Dockerfile from the target, no host mounts, no
published TCP ports, no Docker socket, no production secrets, and no runtime
outbound egress. The Docker **image build** is a separate administrator action
which CAN contact package indexes: transitive wheel versions/hashes are not
locked and the build is not fully supply-chain reproducible. A verified offline
wheelhouse or hash-locked dependency preparation is future work; don't market
this as general secure dependency support.

The independent verifier obtains HTTP status codes for 1–8 explicitly requested
GET paths, with checks separately supplied by the user; application stdout is
ignored. Positive contract = `HTTP_CHECKS_PASSED`; negative =
`HTTP_CHECKS_FAILED`; incomplete evidence / unsafe configuration / missing
image / failed cleanup = `BLOCKED`. All statuses explicitly maintain
`security_verdict: NOT_EVALUATED`, `finding_status: null`. None imply FIXED.

## Install/verify on user's existing Windows project

Overlay only the contained `securitylab`, `tests`, `docker`, `examples`, and
`docs` files onto the matching directories. Do not overwrite `.securitylab`,
Git configuration, Ollama/model volume, or Hermes. New command:

```powershell
py -3 -m unittest discover -s tests -p test_fastapi_probe.py -v

docker build -f docker/FastAPI.Dockerfile -t securitylab-fastapi:local .

$state = Join-Path $env:TEMP 'SecurityLab_S63c_DemoState'
$p = py -3 -m securitylab --state "$state" repo add ".\examples\s6_repos\python_fastapi_min" --name "FastAPI fixture" | ConvertFrom-Json
if ($LASTEXITCODE -ne 0) { throw 'repo add failed' }
$s = py -3 -m securitylab --state "$state" repo snapshot $p.id | ConvertFrom-Json
if ($LASTEXITCODE -ne 0) { throw 'snapshot failed' }
py -3 -m securitylab --state "$state" repo fastapi-probe $s.snapshot_id --entry main.py --expect '/health=200' --expect '/__missing__=404' --execute
```

Expected: `HTTP_CHECKS_PASSED`, `cleanup=PASS`, `target_image_id` (FastAPI)
plus `image_id` (verifier), `security_verdict=NOT_EVALUATED`.

The image build is **not** done automatically by `repo fastapi-probe`; this is
intentional. If pip/download fails during the build, do not disable runtime
network isolation. Check the build error separately. Do not rebuild Ollama or
Hermes. A failing or unsupported app returns BLOCKED/FAILED rather than a false
security verdict.

## What remains

The profile is only one source file with image-provided dependencies and
hardcoded ASGI name `app`. Real repo requirements, multi-file packages,
non-HTTP services, Node/Go, application auth and database tests, independently
specified security invariants, Red before Blue, a real candidate Git patch
workflow, Dashboard and recovery are not implemented by S6.3c. `scan` remains
BLOCKED. Next: Windows live acceptance, then S6.4 generic safe adapter plans
and S7 independent Red/Blue scenario checks, without removing existing gates.
