## Implemented

`repo fastapi-package-probe` adds a **separate opt-in profile** for one selected
service directory. It accepts up to 31 UTF-8 `.py` sources (96 KiB each, 180 KiB
combined), with importable Python module names and explicit `__init__.py` files
in nested packages. The path `--entry` is repository-relative and must be
inside `--service` (default snapshot root). Its module must expose `app`.
Only `.py` source files from a previously hashed, verified snapshot are
transferred. Source SHA-256 values are rechecked through opened file handles;
a second snapshot verification occurs after selection. The SHA-256 over the
selected sorted member identities is included in the broker's binding and
report. JSON payload limit remains 256 KiB.

The existing version-1 `job_contract` is **unchanged** for older modes (flat
filenames). New version 2 allows bounded relative Python package paths with no
traversal, Windows path separators, or shell fields. The trusted
`container_worker` materializes nested files into its empty, size-limited
`/work` tmpfs before executing a developer-authored launcher. No source is
executed on the host. This requires rebuilding the `securitylab-demo:local`
Docker image to install the updated worker and rebuilding the FastAPI image
based on it. No Hermes/Ollama/model rebuild is required.

The actual target still runs in a separate non-root, read-only, resource-limited
container. A second container obtains HTTP observations over an ephemeral
Docker `--internal` network, with no host-published ports or mounts. Both image
IDs are pinned by the trusted host, and the receipt is bound to checks, image
IDs and payload hash. The fixed independent HTTP verifier remains the existing
S6.3b one. Allowed status: `HTTP_CHECKS_PASSED`, `HTTP_CHECKS_FAILED`, or
`BLOCKED` (on insufficient evidence/cleanup). Security verdict remains
`NOT_EVALUATED`; **there is no automatic finding or FIXED**.

## Limits, honest trust boundary

- A restricted Python/FastAPI package profile, **not** generic arbitrary
  repository execution, not automatic dependency resolution, not scanning.
- Only preinstalled FastAPI+Uvicorn (direct version pins; transitive hashes
  are not locked). `pyproject.toml`, `requirements.txt`, repo Dockerfiles and
  scripts do not control execution or trigger install.
- No databases, auth oracle, secret provisioning, templates or non-`.py` assets.
  Unsupported source trees or missing dependencies are blocked/fail.
- Snapshot creation and rechecks on Windows are best-effort against a host
  actively modifying files, not a hostile-host race-proof filesystem boundary.
- All existing limits and known caveats about Docker/kernel escape and orphan
  containers on hard kill apply.

## Install and Windows acceptance

Apply ZIP overlay to existing S6.3c project, **without removing `.securitylab`**.
Files in overlay are individually listed in `manifest_s63d.json`.

```powershell
py -3 -m unittest discover -s tests -p test_package_probe.py -v

# Required: install new schema-v2 worker INTO both images.
docker compose build demo
docker build -f docker/FastAPI.Dockerfile -t securitylab-fastapi:local .

$state = Join-Path $env:TEMP 'SecurityLab_S63d_DemoState'
$p = py -3 -m securitylab --state "$state" repo add ".\examples\s6_repos\python_fastapi_package" --name "FastAPI multi-file" | ConvertFrom-Json
if ($LASTEXITCODE -ne 0) { throw 'repo add failed' }
$s = py -3 -m securitylab --state "$state" repo snapshot $p.id | ConvertFrom-Json
if ($LASTEXITCODE -ne 0) { throw 'snapshot failed' }
py -3 -m securitylab --state "$state" repo fastapi-package-probe $s.snapshot_id --entry app/main.py --expect '/health=200' --expect '/version=200' --expect '/__missing__=404' --execute
```

Expected: `HTTP_CHECKS_PASSED`, `cleanup=PASS`, `source_file_count=3`,
`security_verdict=NOT_EVALUATED`. The real Windows result is not claimed until
user supplies the log. Keep `.securitylab`, Hermes and Ollama volumes unchanged.
