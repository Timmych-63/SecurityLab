# S6.1 — bounded repository inventory + project registry

Date: 2026-11-09. Base commit `6bf3f56` (S5.1).

## Scope completed

- `repo inspect <path>`: read-only, bounded, deterministic metadata inventory of the
  repository path. Recognizes Python, Node.js, Go, Rust and Java manifests;
  language extensions; per-directory service markers; test file counts;
  declaration-only framework hints and npm script **names** (not bodies).
- `repo add <path> [--name]`, `repo list`, `repo show <ID>`: project records in
  the existing SQLite state database. `repo show` compares the saved metadata
  fingerprint with a new read-only inventory. Existing state and runs remain.
- `profiles`: lists recognition profiles. All execution profiles remain
  `NOT_IMPLEMENTED`; `scan` still returns `BLOCKED`.
- Three synthetic sample repositories under `examples/s6_repos` (Python,
  Node.js, Go) support inventory examples and further tests.
- Inventory rejects root symlinks/junctions, does not recurse through links or
  reparse points, skips special files, excludes dependency and Git directories,
  limits entries/files/depth and manifest reads; it never runs project code.
- Reject `.securitylab` state within a registered repository before creating
  a store in the CLI; `add_project` enforces the same guard internally.

## Trust boundary and limitations

Inventory is host-side metadata discovery and is not yet suitable for consuming
repositories actively modified by a hostile concurrent process. The metadata
fingerprint incorporates names/sizes/mtime and is **not** a source-content hash,
Git revision, atomic snapshot or security evidence. Do not use it as an input to
`FIXED` decisions. Potential secrets are identified by filename only and never
opened. Source code and README instructions are not sent to Hermes/Ollama.

No startup/build/test/npm/pip/go commands are inferred or executed, even if
provided in package.json. The user must eventually approve bounded execution
profiles in an isolated copy. Profiles are detection-only at this stage; no
claim of a production security scan, Git isolation, automatic service startup
or arbitrary-language support is made. The source directory is not changed.
