# S9.1.2 — пустой анализ с пояснением

Обновление поверх S9.1.1. Не исправляет качество рассуждений модели и не подставляет ей готовые уязвимости.

## Что показали журналы

В первой попытке модель предложила неописанные ресурсы, перепутала роли пользователей и описала поведение, которое само по себе не является нарушением доступа. Во второй вернула пустой массив cases и пояснение в error. Раньше дополнительное поле превращало этот исход в отказ схемы.

Теперь допускается только такая ограниченная форма:

```json
{"cases": [], "error": "No supported hypothesis can be justified"}
```

error — необязательная строка от 1 до 1500 символов, допустимая только при пустом cases. Другие дополнительные поля, неверные типы и пояснение error вместе с непустыми проверками отклоняются. Ответ модели сохраняется без автоматической подстановки маршрутов или пользователей.

Итог пустого анализа:
- status: NEEDS_REVIEW
- analysis_outcome: NO_SUPPORTED_HYPOTHESES
- security_verdict: NOT_EVALUATED
- finding_status: null
- analysis_note: исходное пояснение модели (не доказательство)
- наблюдение приложения и Blue не запускаются.

Сообщение пользователю: «Анализ не дал проверяемых гипотез. Проверка приложения не выполнялась; безопасность не оценена».

Также исправлена причина отклонения маршрута: непредусмотренный HTTP-ресурс больше не описывается так, будто это обязательно путь Python-файла.

## Установка

1. Остановить dashboard. Сохранить резервную копию заменяемых файлов.
2. Скопировать содержимое update в корень SecurityLab с заменой.
3. Из корня проекта:

```powershell
py -3 -m unittest discover -s tests -p "test_discovery.py" -v
docker build -f docker/Hermes.Dockerfile -t securitylab-hermes:s4 .
py -3 -m securitylab.dashboard --state "$env:TEMP\SecurityLab_S72_DemoState"
```

Новая модель не скачивается, GPU и Docker-изоляция не меняются. Старые результаты остаются прежними: обновление не переписывает исторические квитанции.

Повторять длительный AI-запуск только ради нового статуса необязательно. Если модель снова отдаст этот пустой ответ, он завершится как отсутствие проверяемых гипотез, а не ошибка формата. Считать приложение безопасным по такому исходу нельзя.

## Проверка

42 теста: 16 discovery и 26 access-ai. Проверено сохранение пояснения, отсутствие вызовов исполнителя и Blue, неизменность NOT_EVALUATED, отказ для недопустимых схем и сохранение успешной ветки независимой проверки. Docker и настоящая модель локально не запускались.

Следующая содержательная задача — добиться обоснованных гипотез от модели и проверить их на независимом исполнителе. Этот патч лишь честно отражает отсутствие результата анализа.
