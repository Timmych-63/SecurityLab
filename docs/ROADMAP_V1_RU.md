# SecurityLab — оставшиеся шаги до V1

Актуально 12 ноября 2026. Последний реальный успешный AI-цикл: S7.2.1, run c6764da52c7a4f86ad2bcd21e73233b0, два Blue-кандидата, независимый повтор, отдельный Git-коммит. S7.3 реализуется как расширение политики, его Windows-приёмка ещё впереди.

Универсальность означает подключение разных проектов через профили. Обещание «тестировать любое приложение любого стека» не является достижимым критерием завершения первой версии. Состав профилей V1 и приёмочные репозитории ещё предстоит выбрать явно.

| Этап | Что осталось сделать | Когда считаем завершённым |
|---|---|---|
| S7.3, сейчас | Проверки 401/404, третьего пользователя, сохранения поведения | Восемь независимых случаев проходят на реальном кандидате и recheck в Windows; неподходящие кандидаты не получают FIXED |
| Завершение S7: переносимость | Запуск на другом небольшом FastAPI-приложении, другие маршруты/данные и внешняя политика | Новый проект подключается настройками, без изменения ядра под его имена |
| Завершение S7: работа агентов | Red анализирует выбранный проект и предлагает новые проверяемые гипотезы/тесты; Blue получает нужный контекст и может предлагать ограниченные многомодульные изменения | Новая находка воспроизводится до исправления; фактический patch проходит независимые проверки и регрессионные тесты; AI не назначает себе успешный статус |
| S8: дашборд | Проекты, настройки профиля, запуск/остановка, ход Red/Blue, находки, доказательства, diff, отдельные Git-ветки, история и причины отказов | Основной сценарий выполняется через локальный UI; UI и CLI используют общий backend и реальные данные |
| S9: устойчивость | Общая очередь и состояние AI/Docker, отмена, ограниченные повторы, восстановление после падения, очистка контейнеров, обновление без потери данных | Проверены принудительное завершение, перезапуск, лимиты, отсутствие двойного выполнения и ложных успешных статусов |
| S10: приёмка V1 | Зафиксировать поддерживаемые профили, несколько разных репозиториев, полный набор позитивных/негативных проверок, установка и документация | Все заявленные сценарии воспроизводятся на Windows; ограничения видны пользователю |

Не откладывать дашборд ради бесконечного расширения CLI или коллекции учебных кейсов. Очередь и API, необходимые UI, могут разрабатываться вместе с S8; S9 — проверка устойчивости всего цикла.

## Точка завершения

Предлагаемый критерий V1: пользователь устанавливает систему, подключает разные проекты заявленных профилей в изолированных копиях, через дашборд запускает и наблюдает полный цикл, получает подтверждённую находку и проверенный коммит в отдельной ветке, просматривает доказательства и diff, останавливает/восстанавливает работу. Обязательные позитивные и негативные сценарии проходят на нескольких разных испытательных проектах. Новый проект поддерживаемого профиля не требует изменения ядра. Нет автоматического merge/push и утверждения о полной безопасности приложения.

## После V1

Расширять стековые адаптеры и классы уязвимостей, добавлять многосервисные окружения и миграции БД, улучшать модели/планирование на измеряемом наборе задач, затем интеграции CI и командную работу. Это дальнейшее развитие, а не причина переносить завершение V1 бесконечно. Облачные модели — только отдельная явная настройка с понятной передачей данных.
