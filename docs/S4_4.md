# S4.4 — reviewed ownership variants

The reported Blue proposal used a local owner variable after the existing
401/404 guards. Its behavior is correct for the known synthetic fixture,
but S4.3 rejected it because its AST differed from the single template.

Four complete reviewed module ASTs are now admitted: direct comparison in
either operand order and a local `owner` assignment followed by comparison
in either order. This is a finite whitelist, not general semantic analysis.
All other statements, records, function signature and return values remain
fixed. Unknown variants remain NEEDS_REVIEW and are not executed.

Summary records identify the reviewed variant and explicitly state that S3
executes canonical FIXED, not the original AI proposal. Original proposal and
its hash remain recorded. This release does not implement arbitrary patch
execution or production project analysis.

Validation: full unit suite and focused AI workflow regression, including
developer-owned variant behavior across 15 user/record combinations each,
rejection of mutated variants and owner access before the missing-record
guard. Docker transport in local workflow tests is simulated. Live Windows,
Docker and Qwen verification must be performed on the user's machine.

Next architectural milestone: independently test actual candidate code inside
a dedicated sandbox, bind evidence to its exact bytes, freeze externally
defined regression/security checks, and retain human review for unclear
requirements. Do not remove the AST gate before that runner is implemented.
