# S6.2.1 — Windows file identity fix (2026-11-09)

Основание: реальный лог пользователя с Windows / Python 3.13.6, где команда
`py -3 -m unittest discover -s tests -p test_snapshots.py -v` завершилась
`FAILED (failures=2, errors=9)`, а CLI —
`ERROR: Source changed between enumeration and open`.

## Подтверждённая причина

В Python 3.13 на Windows `os.DirEntry.stat(follow_symlinks=False)` возвращает
`st_dev=0, st_ino=0`, тогда как свежие `Path.lstat()` и `os.fstat(fd)` могут
возвращать настоящие идентификаторы. S6.2 некорректно требовал их равенства.
См. https://docs.python.org/3.13/library/os.html#os.DirEntry.stat

## Изменения

- При обходе репозитория и при проверке снимка сначала анализируем результат
  DirEntry для классификации, затем запрашиваем `Path.lstat()` заново.
- Сравнение исходной записи с новой учитывает нулевые неизвестные идентификаторы,
  но всё ещё сверяет тип, размер и время изменения; ссылки/reparse отклоняются.
- Открытый файловый дескриптор проверяется **строго** против свежего `lstat()`:
  `st_dev/st_ino/st_size/st_mtime_ns`; затем повторно проверяется после чтения.
- SHA-256 файла, проверка manifest и соответствие SQLite продолжают действовать.
- Не менялись инструменты/доступы AI, Docker, модели, база данных и CLI.

## Проверки

- Linux: 17/17 S6.2+hotfix unit-тестов PASS (два новых теста), 22/22 S6.1 PASS.
- Новый тест эмулирует нулевые `st_dev/st_ino` в DirEntry при обычном создании
  и верификации снимка; старый S6.2 падает в таком сценарии.
- Новый негативный тест: подмена исходного файла после listing отклоняется.
- Настоящий Windows-прогон **ещё не получен**; нужен результат пользователя.
- Доверенная сторона запуска должна работать с собственной/контролируемой копией;
  переносимость не даёт атомарного снимка при атакующем изменении дерева.

## Установка на S6.2

Распаковать overlay и скопировать с заменой только
`securitylab/snapshots.py` и `tests/test_snapshots.py`.
Существующую `.securitylab`, том Ollama и Docker не трогать.

В PowerShell из корня проекта:

```powershell
py -3 -m unittest discover -s tests -p test_snapshots.py -v
py -3 -m unittest discover -s tests -p test_repository.py -v
```

Если тесты PASS, проверить на Python example:

```powershell
$state = Join-Path $env:TEMP 'SecurityLab_S621_DemoState'
$project = py -3 -m securitylab --state "$state" repo add ".\examples\s6_repos\python_api" --name "Python example" | ConvertFrom-Json
if ($LASTEXITCODE -ne 0) { throw 'repo add failed' }
$snapshot = py -3 -m securitylab --state "$state" repo snapshot $project.id | ConvertFrom-Json
if ($LASTEXITCODE -ne 0) { throw 'repo snapshot failed' }
py -3 -m securitylab --state "$state" repo verify-snapshot $snapshot.snapshot_id
```

Ожидается `VERIFIED_CONTENT_HASHES` и `execution_permission: DENIED`.
Это проверка копии, а не разрешение запуска или сканирования приложения.
