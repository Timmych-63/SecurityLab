# SecurityLab UI — «Lucian Lab»

Настольный веб-интерфейс (с адаптацией к телефону) для локальной лаборатории проверки
безопасности SecurityLab. Визуальный язык построен **с нуля** на дизайн-токенах библиотеки
[lucian-uxui-prompt](https://github.com/Seokwoooo/lucian-uxui-prompt) (MIT): тёплая бумага,
чернильный текст, фиолетовый акцент, кольцевые тени вместо бордеров, «чернильные» пилюли
навигации, пружинные easing'и. Функциональный объём — по документу `SecurityLab_Dashboard_Prompt_RU.md`.

Реализован как **демо-фронтенд с явным режимом работы**: серверные действия не изображаются,
все прогоны помечены «демо», отказы показываются с причиной. В поставку входит
**референсный сервер endpoint'ов** (Node, без зависимостей) — см. раздел «Референсный сервер».

**Режимы интерфейса (видны и на телефоне, в шапке):** «Демо в браузере» → «Сервер симуляции»
(референсный сервер, `demo: true` у прогонов) → «SecurityLab подключён» (боевой backend,
`mode: securitylab-core`) + отдельная метка «Нет связи / Связь потеряна» при ошибке опроса.
Демосервер — инструмент разработки UI, не параллельное ядро SecurityLab.

## Запуск

```bash
npm install
npm run dev            # dev-сервер http://localhost:5173
npm run build          # статика в dist/
npm run preview        # локальный сервер для собранной dist/
npm run serve:api      # референсный сервер endpoint'ов → http://127.0.0.1:8765
npm run test:contract  # 49 контрактных тестов client↔server (поднимает сервер сам)
```

Внимание: открывать `dist/index.html` двойным кликом (file://) нельзя — браузеры блокируют
ES-модули с file-протокола. Используйте `npm run preview` или любой статический сервер
(`python3 -m http.server -d dist`).

Если вы обновляете уже открытую сборку — обновите страницу с очисткой кеша (Ctrl+F5):
`index.html` кешируется браузером, а хеши asset-файлов меняются вместе со сборкой.

Подключение к серверу — на экране «Интеграция»: запустите `npm run serve:api`, введите
loopback-адрес и нажмите «Проверить соединение» (проверяется `GET /api/health`). При успехе
интерфейс переключается на HttpAdapter — в шапке появляется метка режима с адресом; при
неудаче честно остаётся прежний режим. Переключение живёт до перезагрузки страницы; кнопка
«Перепроверить соединение» при отказе переводит шапку в «Связь потеряна», не подменяя данные.

```
UI (React-экраны, hash-роутер, светлая/тёмная тема)
  ↓ всё содержимое рендерится декларативно (экранирование React),
  ↓ innerHTML / dangerouslySetInnerHTML не используются
SecurityLabAdapter — типизированный контракт (src/adapter/types.ts)
  ├── DemoAdapter — демо-данные в браузере + честные отказы без backend;
  │     симуляция активного прогона детерминирована и переживает
  │     перезагрузку страницы (localStorage), задача не перезапускается
  └── HttpAdapter (src/adapter/http.ts) — клиент референсного сервера:
        loopback, GET /api/csrf + X-CSRF-Token, abort по тайм-ауту, JSON
Референсный сервер (server/server.mjs, zero-dep Node ≥ 18, только loopback)
  ├── реестр проектов/снимков/прогонов — реальные CRUD-операции
  ├── предпроверка — реальные вызовы: docker version / image inspect, TCP-пробой модели
  ├── диагностика — реальные os.* (CPU/память); GPU — null = «нет данных»
  └── seed.json — тот же датасет, что и в демо (node scripts/dump-seed.mjs)
Боевой backend (securitylab: cli.py, access_ai.py, ai_workflow.py, storage.py,
```

Полная карта «действие UI → ожидаемый модуль → endpoint» — на экране «Интеграция» (16 строк);
все GET/POST реализованы референсным сервером.

## Референсный сервер: что реально, а что симуляция

**Реальные операции** (над хранилищем сервера и хостом): health, CSRF-токены (1 ч) и проверка
Origin (только loopback) на изменяющих операциях; регистрация проекта с настоящей проверкой пути
через `fs.stat` (отклонит несуществующий путь с причиной); создание снимка (запись в реестре,
без Git-операций); создание прогона (202 + run_id) и лимит «один активный»; подтверждённая отмена
(состояние замораживается на момент отмены, этапы честно помечаются «остановлено отменой»);
предпроверка (`docker version`, `docker image inspect`, TCP-пробой адреса модели — отсутствие
docker честно фиксируется, а не изображается); диагностика CPU/памяти из `os.*`; артефакты только
по идентификаторам (traversal отклоняется); exportPatch.

**Симуляция (помечена честно):** ход прогона — сценарий по секундам из seed.json (как в демо),
`demo: true` в каждом прогоне; HTTP-вызовы Hermes не выполняются (TCP-пробой вместо них);
Docker-контейнеры не запускаются — воспроизведение нарушения остаётся за боевым backend.

## Графики (lucian #095 / #096)

- **«Запуски» — обзор из двух карточек** над фильтрами: столбцы «прогоны по дням» (14 дней,
  стопка по статусам: мята — завершён, фиолет — выполняется, охра — лимит, красный — ошибка,
  серый — отменён/очередь; чернильный тултип при наведении на день) и линия «длительность
  завершённых прогонов» со средней/медианой, скрабом по точкам (тег «X мин · run-…») и
  пульсирующей точкой на последнем значении. Оба графика построены из реальных данных журнала
  и **реагируют на фильтры**.
- **«Деталь прогона» — «Длительность этапов»**: горизонтальные полосы пропорционально реальным
  таймингам этапов; идущий этап тикает вместе с «сейчас», цвет этапа = состоянию, подписан
  легендой с текстом.
- Всё без chart-библиотек: SVG/div на токенах темы, пружинная анимация роста, отключается при
  `prefers-reduced-motion`. Числа — `tabular-nums`, цвета статусов всегда продублированы текстом.

## Честность отображения (проверено в браузере)

- Раздельные статусы: выполнение ≠ `security_verdict` ≠ `finding_status`.
- Зелёным (мятным) отмечен **только** finding POLICY_VIOLATION_NOT_OBSERVED_ON_CHECKED_FIX. BLOCKED / TIMEOUT / NEEDS_REVIEW /
  NOT_EVALUATED не показываются зелёным; PASS smoke — нейтрально-серый и сопровождается
  пояснением «smoke ≠ отсутствие уязвимостей».
- Отсутствующий этап и отсутствующий артефакт показываются как «не выполнен» / «отсутствует
  с причиной» (очистка контейнера), а не как успех.
- Отказы: второй запуск при активном (честный отказ, не очередь), отмена (операция не
  подтверждена исходниками — различие «ожидание отмены»/«подтверждённая остановка»),
  создание снимка, регистрация проекта, отсутствующая модель (`hermes-experiment.toml`),
  недоступный backend — все состояния с объяснением.
- Недоверенный контент: в демо-логах и diff есть строки `<script>alert('xss')</script>` и
  `<img src=x onerror=alert(1)>` — отображаются текстом (проверено: 0 созданных элементов,
  теги/обработчики не исполняются). HTML-отчёт не рендерится, показывается текстом.
- Артефакты отдаются по идентификаторам; запрос вида `../../etc/passwd` отклоняется
  адаптером (проверка traversal). Хеш — журнал целостности, не подпись и не гарантия.
- Экспорт патча доступен только при подтверждённом коммите; merge/push и кнопка
  «принять как безопасное» отсутствуют; политика не редактируется из UI.

## Проверка удобства (UX-обход, выполнен при сборке)

Обход в headless-браузере: десктоп 1440×900 и телефон 390×844, светлая и тёмная темы,
полный сценарий оператора «проект → форма → предпроверка → запуск → наблюдение → разбор».

**Найдено и исправлено:**
1. В списке прогонов колонка «Сейчас» не показывала активный этап симуляции — список
   получает развёртку сценария (`liveRun`), статус и этап обновляются каждую секунду.
2. `run_id` переносился на две строки в узкой колонке — идентификатор не переносится,
   метка «демо» вынесена на отдельную строку.
3. При повторном открытии обновлённой сборки браузер может держать закешированный
   `index.html` (старые имена asset-файлов) — приложение при этом работоспособно, но
   рекомендуется Ctrl+F5 (замечание внесено в раздел «Запуск»).
4. При пересборке на токенах lucian активная вкладка детали прогона стала невидимой
   (текст цвета страницы без подложки) — активная вкладка получила собственную чернильную
   заливку-пилюлю.

**Осознанные решения ради удобства:**
- Форма запуска — один экран с пронумерованными разделами вместо пошагового мастера:
  экспертный инструмент, все параметры видны одновременно, ошибки полей конкретные.
- Тройной статус закреплён вверху детали прогона — пользователь не путает выполнение,
  вердикт и статус находки; каждое нестандартное состояние сопровождается объяснением
  («BLOCKED — не „проект безопасен"» и т.п.).
- Цветовая семантика lucian-токенов: мятный — только подтверждённое отсутствие нарушения на проверенном исправлении;
  фиолетовый акцент — живой процесс и активная навигация; янтарный — лимит времени
  и «ожидаем ответ»; красный — блокировки и отклонения; серый — «не оценивалось».
  Цвет всегда сопровождается текстом статуса.
- Долгая генерация показывается как «ожидаем ответ» с редким «дыханием» маркера —
  без выдуманных процентов.
- Отказы показываются рядом с действием, которое их вызвало, с конкретной причиной.
- Мобильные таблицы превращаются в пары «поле — значение» без потери данных проверок.
- Клавиатура: видимый фокус на всех действиях, вкладки прогона управляются ←/→,
  Esc закрывает диалоги.

## Что работает сейчас (в этой сборке)

- Чтение всех разделов на демо-данных с явной пометкой «демо».
- Демо-прогон из формы: симуляция развивается в реальном времени, переживает перезагрузку
  страницы, не перезапускает задачу.
- Все попытки Blue с diff, причинами отклонения, независимыми проверками и recheck.
- Экспорт подтверждённого патча (файл помечен как демо).
- Подключение к референсному серверу: регистрация проекта (реальный `fs.stat`), снимки,
  создание/отмена прогонов, реальные CPU/память в диагностике, предпроверка с реальными
  docker/model-проверками.
- Графики журнала (бары по дням, длительности) и этапов прогона.
- Светлая и тёмная темы (сохраняются), мобильная адаптация, клавиатурная навигация.

## Что отложено (требует боевой backend)

- Реальные Docker-прогоны с воспроизведением нарушения и Git-коммитом патча.
- Очередь фоновых заданий; восстановление после рестарта не обещается.
- WebSocket/SSE-события (документом не подтверждены; состояние отдаётся по GET).
- GPU-метрики — `os.*` не знает о GPU, показывается «нет данных».
- Редактирование политик/профилей, поддержка стеков помимо FastAPI.

## Для настоящей интеграции

Пришлите репозиторий SecurityLab (`securitylab/cli.py`, `access_ai.py`, `ai_workflow.py`,
`storage.py`, `hermes_adapter.py`, `ai_config.py` и примеры summary/receipts) — тогда
карта API сверяется с кодом, референсный сервер заменяется боевой реализацией с тем же
контрактом, а демо-ветка остаётся тестовым контуром.

## Ключевые дизайн-решения (и что сознательно исключено)

Концепция — «Lucian Lab»: палитра 1:1 из `src/tokens.css` библиотеки lucian-uxui-prompt —
тёплая бумага `#F4F2EE` с чернильным текстом `#16151B` и фиолетовым акцентом `#6A57F2`
(тёмная тема `#07080D` / `#F4F0E8` / `#B7A4FF`), градиент логотипа `#7B61FF → #3D8BFF → #1FB89A`,
пружинные кривые `cubic-bezier(.34,1.45,.64,1)`. Фирменные приёмы lucian: кольцевые тени
`0 0 0 1px var(--line)` вместо бордеров, скользящая чернильная пилюля в навигации,
чипы на мягких подложках, таймлайн этапов с цветными узлами, парящий орб пустых состояний,
переключатель темы-бегунок. Все анимации отключаются при `prefers-reduced-motion`.

Исключено по требованию ТЗ («спокойный рабочий инструмент»): декоративные метрики-гиганты,
лендинг-герой, глубокая вложенность карточек; цвет статуса никогда не используется без
текста. Эмодзи в интерфейсе отсутствуют — только штриховые SVG-иконки.
